volatile tells the compiler the value can change outside the normal program flow, so it must not cache it in a register, reorder or delete
'redundant' reads/writes - every access in the source becomes a real load/store on the bus
Thus the compiler wont optimize this variable anymore

This is needed in the following situations
1. Memory mapped hardware or peripherals
2. Variables shared between ISRs of Interrupts
3. Variables shared between threads/core without synchronization


E.g.
volatile int flag = 0;
while(flag == 0){}

Without volatile, the compiler would read flag only once since it is not updated inside the loop,
But now, the value of flag register is read every cycle due to volatile
